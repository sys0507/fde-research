# Portability, interface identifiers, and example data

The package's methods work from project inputs and are not bound to a particular enterprise. Organization names have been removed from the prototype reference documents; folder conventions are replaceable project examples.

The scenario template keeps configurable product/organization fields and a product-initial mark; these are not a fixed vendor brand. The optional `ui.simulation_label` defaults to "Simulation · Not a production system"; for teaching it can be changed to a teaching-simulation notice, but the simulated nature must remain stated. Without a real run as the basis, do not remove all simulation markers for the sake of appearance.

The warehouses, colors and sizes, quantities, and dates in the logistics scenario, and the maintenance assistant, staff, salaries, gross margin, and model costs in the quotation examples, only demonstrate writing/calculation. They must not be used as facts for a new project or as default industry parameters. Real projects replace the example content and recalculate; teaching supplements are created only with explicit authorization in this round and kept separate from originals.

The package does not require an enterprise logo, author watermark, or vendor advertising. The two Word builders clear the author, last-modified-by, and comments fields; this does not guarantee that all output metadata from third-party Office/diagram tools is empty. If customer templates and actual tools carry identifiers, check the outputs according to project requirements.

Codex's `artifact operation marker` is an execution marker of a specific host and is not called on the generic path; the Word script's `marker()` is a structural marker for the contents field; the HTML `brandmark` is a style/product field. These three are not the same kind of watermark.

Valuable technical tool names and method sources are kept: the Archify enhancement path, the optional Codex adaptation, method attributions, the JSON Schema namespace, and runtime price sources are not deleted blindly for "debranding". Prices and capabilities are verified independently at run time; an example vendor is not the only choice.
