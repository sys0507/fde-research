# Inputs, assumptions, and continuation

## Read and select versions

Business outputs establish what to buy, readiness establishes resource/cooperation conditions, and final design establishes what to build. Record each adopted source's relative path, title, version/date, status, use, and hash. Reference originals without copying entire asset sets; revisit consequential interface/cost/resource/quality evidence. Diagrams cannot replace the full design. Old drafts/trials/branches remain historical.

Explicit amendments and effective authority take priority; newer timestamps alone do not confer approval. Record adoption/exclusion reasons. Oral additions retain role/date/scope/content/status. Existing authorized commercial choices persist. If this task excludes equipment procurement despite earlier suggestions to obtain quotes, disclose resource conditions/separate procurement without seeking quotes.

Applied is not activated; requestable is not allocated; promised data is not received; prototype is not finished backend; submitted report is not customer approval. Preserve conflicts and recommend treatment instead of altering facts for a feasible schedule. Missing scope permits a conditional supported draft, not false confirmation.

Use [inherited mode](inherited-proposal.md) for a designated previous baseline. Permission to make assumptions does not authorize replacing adopted price, duration, or API budget.

## Propose computable assumptions

Recommend within existing constraints. Without names use hypothetical IDs such as P-FDE1 and necessary short-term specialists, keeping one ID across roles and part-time daily capacities/windows. Without a date start at working day 1 after prerequisites are met; do not imply holidays are handled.

Without actual costs state vendor assumptions. Primary continuous commitment uses payroll periods, employer contributions, and reservation share; genuinely releasable support uses full hourly cost. Record gross salary, employer/employee contribution boundary, overhead inclusions, and basis. A sales day rate is not employee cost, and a cheap hourly assumption cannot hide full salary periods.

Each assumption has ID, condition/value, reason, basis/formula, applicability, work/cost/date impact, evidence/role/milestone, and change treatment. Distinguish fact, preset, confirmed, revised. Rates/margins are internal; customer inputs/interfaces/resources/pilots/scale/reuse/iterations/commercial/tax conditions are client-visible. Provide separate external and internal assumption documents.

For waiting specify who returns which verifiable output by which working day, dependent work, delay effect, and parallel alternatives. A mock supports page work but not live integration acceptance. Coordination hours and waiting days differ.

After the complete first draft ask a few consequential review questions, usually 3–5, with known fact, recommended assumption, and impact if false. Do not re-ask confirmed payer responsibilities or make users perform professional breakdown/rate research. Without answers retain the draft as pending human review.

## Versioned outputs and revisions

Suggested project layout: `delivery-plan-and-quotation/run-YYYYMMDD-01/v001/`, then v002. Model/results/CSV/numeric facts/calculation manifest at version root are internal. Customer MD/DOCX/acceptance/assumptions go in `client/`; other internal prose in `internal/`; input/delivery indexes and changes at root; rendering in `qa/`. Distribute an explicit customer whitelist, not the entire run ZIP.

1. Read prior input index, model, and report; preserve the version and save new feedback sources.
2. Trace inputs → requirements → packages → acceptance → people/dates → costs → quotation/payments; retain unaffected content.
3. Record version/change reason and use --previous in a new output. Extra people need not shorten duration; reduced daily capacity need not change total hours/price.
4. Rebuild all affected MD/DOCX/tables/assumptions/manifests. Preserve old hashes/rendering; only new final pages validate the new Word.
5. Explain old assumption, new evidence, affected work, hour/cost/duration difference, and fee treatment. Original defects remain repair obligations; added scope/cooperation changes need commercial confirmation.

Mechanical checks prove structure/constraints, not credible unit effort, correct architecture, or approval. State the actual basis/status.
