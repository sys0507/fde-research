# Optional simulation

Use only when explicitly requested for a simulation, demonstration, or exercise. The default processes actual project assets and feedback and never generates enterprise answers.

Save exercise material separately. Identify added systems, resources, accounts, interfaces, and role answers as fictional settings not confirmed by an enterprise. Organize answers by existing Q IDs, preserving unanswered/constrained items instead of making everything green to meet a round target. Respect existing facts, responsibilities, and cutoff; never rewrite originals or forge signatures, credentials, approvals, or test logs.

Explain simulation at the exercise entry. If the user requests business-style deliverables without repeated labels, consolidate provenance in a separate source/production record rather than every title/cell. Keep it traceable and never present results as real verification.

Analyze simulated feedback only when the user asks to incorporate it. Preserve each round/source snapshot; conclusions apply only to that branch. With authorized continuous exercises, first select truly necessary questions, generate corresponding material, and continue. Stop at readiness criteria without inventing questions to fill three rounds or guaranteeing all conditions become satisfied.
